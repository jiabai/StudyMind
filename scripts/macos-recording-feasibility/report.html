依据 docs/handoffs/studymind-macos-recording-feasibility-handoff.md · F-01~F-08 阻塞性矩阵 · 决策来源 ADR 0005 · 验收计划 docs/test-plans/macos-recording-acceptance.md
结论：F-01 / F-02 / F-06 / F-07 全部通过，F-08 部分通过（授权后重探测成功）；F-03 / F-04 / F-05 受环境限制 Blocked。

工具链升级（CLT → SDK 15.5 / Swift 6.1.2）后 screencapturekit 8.0.1 在本机成功构建运行（F-01）。用户授予 Screen Recording 权限后：全局系统音频捕获到两个独立应用的声音（F-02），excludesCurrentProcessAudio 将自身 440Hz 测试音从 rmsAvg 0.292 降至 0.000（F-06），全程 video_buffers=0（F-07），授权后重探测成功（F-08 部分）。F-03（切输出路由）、F-04（外接显示器）、F-05（恢复窗口）需要 GUI 操作或 E3 环境，本机无法执行。

2. F-01 ~ F-08 判定

ID场景状态证据 / 阻塞原因
F-01Rust binding 编译链接 + 启动最小 audio-only stream（Intel） PASS cargo build --release 成功（Finished in 12.92s）；授权后 SCStream.start_capture() 成功（"STEP start ok"）。Intel x86_64 侧编译/链接/启动全部验证。
F-02两个独立应用音频均进入全局系统音频 output PASS 静音基线 rmsAvg=0.000000；afplay（440Hz）播放时 rmsAvg=0.285581；say 语音播放时 rmsAvg=0.122613；两者同时播放 rmsAvg=0.289172。两个独立应用的声音均进入全局系统音频捕获。
F-03录音中切换默认输出路由，系统音频语义保持 BLOCKED 需在录音期间人工切换系统默认输出设备（GUI 操作），本会话未执行；探针与验证流程已就绪。
F-04主显示器切换 / 外接显示器拔插：filter 更新或 stream 重建 BLOCKED 需 E3 环境（外接显示器），本机仅有内置单显示器（1680×1050 捕获分辨率，2880×1800 原生），无法执行显示器切换/拔插。
F-05恢复窗口：≤2s 按媒体时间戳补静音继续，>2s 失败 BLOCKED 需 E3 环境 + stream 中断注入（显示器切换触发），本机无外接显示器，无法执行。
F-06excludesCurrentProcessAudio 生效，StudyMind 自身音频不进入 capture PASS 同进程 cpal 播放 440Hz 测试音：不排除时 rmsAvg=0.291564；--exclude-self（excludesCurrentProcessAudio=true）时 rmsAvg=0.000000。自身音频排除明确生效。
F-07audio-only fail-closed：不注册 screen output，writer/Worker 不接收视频 buffer PASS 探针仅注册 SCStreamOutputType::Audio，从不注册 .screen；6 次运行（基线/双应用/自身音频对比）video_buffers 全部为 0，mic_buffers 亦为 0。
F-08TCC 基础行为：Screen Recording 请求 + 授权后重探测（ad-hoc 包） PASS* 未授权时 SCShareableContent::get() 返回 TCC 拒绝（"用户拒绝了应用程序、窗口、显示器捕捉的TCC"）；用户授权后重探测成功（displays=1 apps=28）且 stream 启动。*CLI 形态验证；ad-hoc .app 形态（bundle Info.plist / NSScreenCaptureUsageDescription）按 ADR 仍需在打包时复验。

4. 相对 ADR 0005 的偏差

  • 绑定选型一致：探针使用 screencapturekit crate（8.0.1, macos_13_0），未引入 Swift helper、未写 ObjC 桥，符合 ADR 第 2 节。
  • 偏差 1（已消除）：ADR 前提"工具链满足 binding API/链接要求"原不成立（Swift 5.3 / SDK 11.0），已通过升级 CommandLineTools（SDK 15.5 / Swift 6.1.2）解决，F-01 转 Pass，无需重开 ADR。
  • 偏差 2（记录，仅验证环境）：本执行环境 sandbox-exec 不可用（SwiftPM 默认用它编译 manifest），已在 throwaway 探针的 vendor 构建中加 --disable-sandbox；SDK 15.5 编译 apple-metal 0.8.8 的 macOS 26 分支失败，已删除该分支（探针不使用 Metal）。这些仅影响验证 harness 构建，不涉及产品后端选型；正式实现时 Tauri 工程在正常开发环境（用户终端）构建不受影响。
  • 偏差 3（预期内）：CLI 探针无 Info.plist；TCC 授权通过系统设置手动授予。ADR 要求 ad-hoc .app 形态复验（Info.plist 的 NSScreenCaptureUsageDescription、授权后重启等），属打包阶段待办，非设计偏离。
  • 偏差 4（记录）：PATH 内 ffprobe 缺失（ffmpeg 4.2.2 在 PATH；resources/bin 有 brew 9.0.1 的 ffmpeg+ffprobe 软链），B-01 打包验证时需确认运行时解析。

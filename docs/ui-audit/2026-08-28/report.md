# StudyMind UI/UX 审查

日期：2026-08-28  
审查方式：Vite 本地预览 + 浏览器截图，默认视口约 1280×720，另测 720×640；未修改产品代码。

## 审查范围

覆盖首次进入、侧栏主题导航、账号菜单、设置分类、收起侧栏、最小窗口和上传失败恢复态。核心用户目标是：选择本地音视频，理解处理进度，得到可校验的文字稿，并继续生成学习整理结果。

## 总体结论

视觉基础是稳定的：米白背景、绿色主色、卡片层级和图标语言统一，上传入口也足够显眼。当前更影响可用性的不是“再加装饰”，而是状态与任务优先级：首屏把不可用的录音放到了与上传同等的权重；错误态和空态会同时出现；设置面板的保存行为没有和分类语义对齐；最小窗口下首要入口会被推到首屏以下。

建议按以下顺序处理：

1. 先修复错误/空状态和设置加载失败后的保存保护。
2. 把上传设为默认主路径，录音降级为次要路径，并保证最小窗口首屏可见上传。
3. 统一设置的即时生效与“保存”语义。
4. 修复对比度、禁用态和可交互语义，再做结果工作区的视觉细化。

## 最高优先级问题

### P0 — 错误态与空态冲突

证据：首屏截图中同时出现历史加载失败和“没有主题”。  
影响：用户无法判断是数据丢失、首次使用还是系统暂时不可用；失败时还没有 Retry。  
建议：将侧栏状态建模为 `loading / ready-empty / ready-list / error`，error 只显示原因和 Retry，空态只在成功返回空列表后显示。

### P1 — 主任务入口排序错误

证据：最小窗口截图中录音卡片先出现，上传入口需要向下滚动；录音在当前环境还处于不可用状态。  
影响：导入文件的用户先看到失败信息，首个有效动作被推迟。  
建议：窄窗口优先显示上传；录音改为“录音”次级入口/折叠区域，或者只有检测到可用音频设备后才提升为并列主入口。

### P1 — 新建课题缺少可见结果

证据：点击首屏“New topic”后，界面仍保持相同状态，仅按钮获得焦点。  
影响：按钮文案暗示会创建可见的课题，但用户看不到变化，也没有被引导到下一步。  
建议：改名为“开始新任务”，点击后将焦点移到上传区域；如果确实要创建空课题，应立即显示标题/编辑状态。

### P1 — 设置加载失败仍允许保存

证据：设置截图显示加载失败，但底部“Save settings”仍可用；控制器在加载失败后保留初始 draft，提交路径仍调用保存。  
影响：一次暂时性读取失败可能把默认 ASR/输出目录写回本机配置。  
建议：增加 `settingsLoadState`，只有成功加载后允许保存；失败时显示 Retry 和 Close，并保留用户未提交改动。

### P1 — 保存语义跨分类混用

证据：基础、学习、缓存、更新、高级页都共用同一个底部保存区。  
影响：用户容易误以为清缓存、检查更新或打开配置文件也需要保存，操作成本和误操作风险增加。  
建议：Basic 只保存 ASR/输出目录；语言要么纳入同一 draft，要么明确“立即生效”。其他分类只保留 Close/Done，存在未保存草稿时再提示。

### P1 — 入口文案没有充分说明数据边界

证据：上传卡片同时强调“Local processing / Privacy first / AI summary”，而 AI 生成流程的文案说明确认后会把文字稿片段发送到云端 LLM。  
影响：用户可能把“本地处理”理解为所有结果都不离开设备。  
建议：在上传入口附近直接分层说明：“音频/视频和本地转写留在设备；生成 AI 洞察前会明确提示发送的文字稿片段”。

### P1 — 低对比度和禁用态叠加

证据：界面大量使用 `--text-soft`、`--text-muted` 和 `button:disabled { opacity: 0.5 }`；其中小字号辅助文字和 warning 色在浅背景上的对比度存在低于普通文本 AA 的风险。  
影响：状态、错误原因、辅助说明在低视力和低亮度环境下更难读；禁用按钮也难以判断是条件未满足还是出现故障。  
建议：提高辅助文字/警告文字对比度；禁用态保留清晰边框和原因文案，不要只靠整体透明度表达。

### P2 — 跨平台窗口控制不一致

证据：界面硬编码 macOS 风格红黄绿 traffic lights，而打包目标同时包含 Windows NSIS 和 macOS DMG。  
影响：Windows 用户会看到不符合平台习惯的窗口操作，尤其是关闭/最大化位置和视觉含义。  
建议：按平台使用原生窗口控制或分别实现平台惯用布局，并验证 Windows、macOS 的焦点与拖拽区域。

## 已具备的基础

- 上传入口具备清晰的拖放/点击动作、格式提示和错误恢复按钮。
- 颜色、圆角、阴影和卡片风格在首屏、设置和菜单之间保持一致。
- 主要区域使用了语义化 region/dialog，按钮有 aria-label，设置导航有 aria-current，状态区使用 aria-live；这是后续做键盘与读屏验证的好基础。
- 代码中已有 reduced-motion 分支、任务进度状态和本地/云端隐私文案，说明产品状态模型的方向是对的，只需要把这些状态更清楚地呈现给用户。

## 证据限制

- 本次通过 Vite 浏览器预览审查，Tauri 原生 IPC 不在浏览器环境中，因此历史、设置读取、录音设备和文件选择器显示了预览失败/不可用状态；这些具体错误不能直接等同于原生包中的运行结果。
- 未在真实 Windows/macOS 原生窗口中验证系统权限弹窗、麦克风设备枚举、文件选择器、音频播放、拖放路径和更新安装流程。
- 未宣称 WCAG 全面合规；对比度为基于当前 token 的风险筛查，仍需要真实 DOM 的键盘遍历、焦点陷阱、缩放、读屏和自动化规则检查。

## 建议的第一轮改动验收标准

- 历史读取失败时只显示错误 + Retry，不显示空态。
- 点击“开始新任务”后焦点明确落到上传区域，并有可见变化。
- 720×640 窗口首屏能看到上传入口和主动作，录音不阻塞主路径。
- 设置读取失败时 Save disabled；成功加载后仅在有草稿改动时启用。
- 上传错误态不再出现嵌套交互元素，Tab/Enter/Escape 行为唯一且可预测。
- 中文、英文的辅助文字和 warning 文案通过对比度检查，并在 200% 缩放下不截断。

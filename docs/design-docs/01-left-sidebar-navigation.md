## 1. 背景与目标

StudyMind 当前所有功能入口都堆在**顶部工具栏**（历史/设置/新建任务图标），历史记录以"点击图标 → 弹出 Sheet"的模态形式呈现。这种结构有两个问题：

1. **历史课题不可见**：用户必须主动打开 Sheet 才能看到过往课题，且 Sheet 遮挡工作区，无法"边看历史边工作"。
2. **功能入口无层级**：新建任务、历史、设置平级摆放，没有体现"课题是核心对象"的产品心智。

本次改造参照腾讯文档左侧抽屉导航范式，将应用布局重构为 **常驻左侧抽屉（可折叠）+ 右侧主工作区** 的结构，让"新建课题"成为始终可达的第一操作，"历史课题"成为随时可回访的列表。

### 设计目标

| 目标 | 说明 |
|------|------|
| 课题即核心对象 | 一个录音 = 一个课题；抽屉里的一行 = 一次完整的处理闭环 |
| 低认知负荷 | 大学生高频短会话，界面只保留当前任务所需信息 |
| 可折叠 | 默认展开看全部课题，需要大工作区时一键收起 |
| 状态可见 | 处理中/已完成/失败、模型下载、更新等状态都有克制指示 |

### 3.2 抽屉结构（自上而下）

| 区块 | 内容 | 行为 |
|------|------|------|
| **头部行** | 抽屉标题区，左侧 16px 折叠/展开按钮（`PanelLeftClose` ↔ `PanelLeftOpen` 类图标），右侧 16px 折叠按钮镜像 | 锁定在抽屉**头部**（不再放底部）。展开态显示品牌名「StudyMind」，折叠态隐藏标题仅保留按钮。视觉参照 WorkBuddy 抽屉头部样式 |
| **主按钮** | `+ 新建课题`（primary，通栏） | 等价于现有 `startNewTaskFromToolbar` → 重置工作流回 waiting_input |
| **我的课题** | 当前激活课题的放大概览卡片（仅处理中/已激活时出现） | 高亮选中态 + 进度条 + 状态文案；点击聚焦该课题。注意：当前课题**同时**在"全部课题"列表中以选中态高亮显示，两处职能不重叠——此处为 quick-glance 概览 |
| **全部课题** | 历史课题列表（**时间倒序**） | 点击 = `openHistoryItem` 加载到工作区；hover 露出 ✎ 改名 + 🗑 删除；当前激活课题在此列表中以选中态高亮 |
| **底部固定区** | `设置`、`账号与 AI 额度` | 打开对应 Sheet；与顶栏入口行为一致 |

> 注：原 v1 的"搜索课题"输入框已按用户决策移除。抽屉顶部"新建课题"按钮直接接"我的课题"分组，节奏更紧凑。

### 3.3 折叠态（56px 窄栏）

仅保留核心图标，垂直排列：

```
[+] 新建        ← primary 圆角方块
────────
▣ 我的课题      ← 当前激活（高亮）
▲ 转写中        ← 处理中课题指示
▤ 全部课题
────────
⚙ 设置
👤 账号
```

折叠后鼠标悬停任意图标显示 tooltip；课题列表不再展示，通过"全部课题"图标展开或点击展开抽屉查看。

## 4. 课题标题方案（自定义标题）

用户决策支持课题自定义标题。本节为该功能的完整设计。

### 4.1 数据模型与持久化

| 项 | 说明 |
|----|------|
| 字段 | `title: string`（必填，非空） |
| 默认值 | 派生自源文件名（去掉扩展名），与现有 `source.displayName` 一致，保证向后兼容 |
| 持久化位置 | Rust 侧 task manifest（需扩展字段，见 §7.3 实施依赖） |
| 读取 | `HistoryListItem` / `HistoryItem` 增加 `title` 字段，由 `getHistory` / `getHistoryDetail` 返回 |
| 唯一性 | **不强制唯一**（允许重名，与文件系统一致心智） |

### 4.2 新建时命名（可选）

在 `HeroUploadZone` 的"已选中文件"状态（`has-selection`）下，于文件信息与操作按钮之间新增一行**可选**标题输入：

```
┌─────────────────────────────────────────┐
│ 🎵 高等数学第12讲.m4a  · 音频 · 84.2MB   │
│ ┌─────────────────────────────────────┐ │
│ │ 课题标题（可选）                     │ │  ← placeholder = 文件名
│ │ 高等数学·第 12 讲导数应用           │ │  ← 用户可填或不填
│ └─────────────────────────────────────┘ │
│                          [×] [开始转写] │
└─────────────────────────────────────────┘
```

- 留空提交时，前端用文件名（去扩展名）兜底，**不阻断**提交流程
- 输入框最大长度 80 字符（防止列表行截断失控）
- 提交时把 `title` 一并传给 `submitTask`，由 Rust 侧写入 manifest

### 4.3 列表内改名（行内编辑）

| 状态 | 视觉与行为 |
|------|------------|
| 默认 | 标题以 `<strong>` 显示，无编辑入口 |
| Hover | 标题右侧出现 ✎ 图标（13px，`#6e6e73`），其余操作（删除）一并出现 |
| 编辑态 | 标题文字替换为 `<input>`（autofocus，选中文本），✎ 变 ✓ 保存 / ✗ 取消；右侧操作区临时隐藏 |
| 保存 | Enter 或点 ✓ → 调用 IPC 保存 title；保存期间 input 禁用 + spinner；成功后更新列表与当前激活态 |
| 取消 | Esc 或点 ✗ → 退出编辑态，恢复原值 |
| 失败 | input 边框转红 + 错误提示，允许重试或取消 |
| 校验 | 非空（trim 后为空则回退原值）；长度 ≤ 80 |

> 改名是低频操作，hover 出 ✎ 符合"渐进式披露"——默认不显示，需要时可见可学习。

### 4.4 顶栏与"我的课题"卡片的标题显示

- "我的课题"卡片、列表项、`TaskStatusBanner`、各详情 Sheet 标题处均统一显示 `title`（不再用文件名）
- 文件名作为次级信息保留在副行或 tooltip（便于用户辨认源文件）

## 6. 交互规范

1. **新建课题**：任意状态可用（含处理中，走现有 `toolbarNewTaskButtonState` 禁用逻辑）。点击后抽屉收起选中态、主区回到 HeroUploadZone。
2. **课题命名（新建时）**：HeroUploadZone 选中态显示"课题标题（可选）"输入框，placeholder = 文件名；留空提交时用文件名兜底，不阻断流程；最多 80 字符。
3. **课题改名（列表内）**：列表项 hover 显示 ✎ 图标，点击进入行内编辑；Enter 或 ✓ 保存、Esc 或 ✗ 取消；保存期间 input 禁用 + spinner；失败时边框转红可重试。校验：trim 后非空，长度 ≤ 80。
4. **课题切换**：点击列表项 → `openHistoryItem`；处理中（`isProcessingStage`）时禁用切换并显示现有禁用原因文案。
5. **折叠/展开**：触发按钮**固定在抽屉头部**（不放在底部），16px 方形按钮，hover 显底色。切换时 width 过渡 `180ms cubic-bezier(0.22, 1, 0.36, 1)`（ease-out-expo 系），内容按不透明度渐变；折叠状态持久化到 localStorage（key `studymind.sidebar.collapsed`）。
6. **删除**：列表项 hover 显示删除图标（复用 `Trash2`），点击弹出 **inline 确认弹层**（定位在该行附近，小型 alertdialog，见 §6.7）；删除成功后从列表移除，若删除的是当前课题则回退 waiting_input。
7. **键盘**：列表项支持 Tab 聚焦 + Enter 打开、✎ 图标聚焦 + Enter 进入编辑、删除图标聚焦 + Enter 弹确认；折叠按钮有 `aria-label`；抽屉为 `<aside>` 语义元素。
8. **无障碍**：选中课题用 `aria-current="page"`；进度条有 `aria-valuenow`；编辑 input 有 `label`（视觉隐藏）+ `aria-describedby` 关联错误提示；删除确认弹层 `role="alertdialog"`。
9. **动效**：仅状态变化（选中/悬停/折叠/编辑态切换）做过渡，不动画化布局属性；尊重 `prefers-reduced-motion`。

### 6.1 inline 删除确认弹层（取代原 HistorySheet 确认）

原 HistorySheet 内的删除二次确认弹窗，迁移为定位在被删除课题行附近的轻量 alertdialog：

- 触发：点击列表项 hover 露出的 🗑 图标
- 定位：相对该课题行，向下偏移 4px 浮出（`position: fixed` + JS 计算，避免父级 `overflow` 裁剪，符合 impeccable 交互设计参考的 overlay 定位规范）
- 内容：⚠ 图标 + "删除此课题？" + 副文案"将永久删除转写、摘要与思维导图" + [取消] / [删除] 按钮
- 行为：复用 `confirmHistoryItemDeletion` / `cancelHistoryItemDeletion`；删除中按钮禁用 + 文案变"删除中…"
- 关闭：点取消 / Esc / 点弹层外任一处关闭；删除完成后自动关闭
- 无障碍：`role="alertdialog"` `aria-modal="true"`，焦点初始落在"删除"按钮（破坏性操作 autoFocus 二次确认按钮是惯例），关闭后焦点回到触发的 🗑 图标

## 7. 实施要点（实现阶段蓝图）

### 7.1 建议组件划分

```
app/src/
├── features/
│   └── sidebar/                      # 新目录
│       ├── AppSidebar.tsx            # 抽屉容器（展开/折叠态切换）
│       ├── SidebarTopicList.tsx      # 全部课题列表（复用 HistoryListItem）
│       ├── SidebarTopicItem.tsx      # 单行课题（选中/进度/改名/删除入口）
│       ├── SidebarCurrentTopicCard.tsx  # "我的课题"放大概览卡片
│       ├── NewTopicButton.tsx        # 新建课题主按钮
│       ├── InlineDeleteConfirm.tsx   # inline 删除确认弹层（取代 HistorySheet 确认）
│       └── useSidebarState.ts        # 折叠态 + 选中课题 id + 编辑态（可测试）
├── features/workflow/
│   └── HeroUploadZone.tsx            # 改造：选中态新增"课题标题（可选）"输入框
```

### 7.2 数据流（复用现有 controller，尽量不新增状态源）

- 课题列表数据源：`useHistoryController().historyItems`（`getHistory()` 已提供时间倒序列表）
- 新建课题：`useTaskProcessingController().startNewTaskFromToolbar`
- 加载课题：`useHistoryController().openHistoryItem`
- 删除课题：`requestHistoryItemDeletion` / `confirmHistoryItemDeletion`（弹层改为 inline，控制器方法不变）
- 选中态：`workflow.taskId`（当前加载课题即选中课题），无需额外状态
- 进度：`workflow.stage` + `workflow.progress`（转写/AI 阶段映射到进度条）
- **课题标题（新增）**：
  - 显示：`HistoryListItem.title` / `HistoryItem.title`（getHistory / getHistoryDetail 返回，需 Rust 侧扩展，见 §7.3）
  - 新建时输入：HeroUploadZone 本地 state，提交时随 `TaskSubmission` 一并传给 `submitTask`
  - 改名保存：新增 IPC `rename_task_title(taskId, title)`，由 `SidebarTopicItem` 调用；成功后更新本地 `historyItems` 与当前 `workflow` 标题

### 7.3 实施依赖（Rust / 数据层，需在编码前对齐）

- task manifest 增加 `title` 字段，默认值 = 文件名去扩展名
- `get_history` / `get_history_detail` 响应增加 `title`
- 新增 IPC 命令 `rename_task_title`，持久化到 manifest
- `submit_task` 接受可选 `title` 参数，未提供时用文件名兜底

### 7.4 App.tsx 改造点

1. 布局容器：`app-shell` → `desktop-window` 内增加 `<AppSidebar>` 作为左侧固定列；主区（顶栏 + workspace）右移。
2. 顶栏：**移除 History 图标按钮**（用户决策，抽屉取代）；**移除新建按钮**（用户决策，抽屉主按钮承担）；保留设置图标与账号/更新 chip。

# StudyMind UI/UX 修复设计规格

日期：2026-08-28  
范围：`docs/ui-audit/2026-08-28/report.md` 中的全部 P0/P1，以及低风险 P2 收尾项。

## 背景

本次 Product Design 审查发现，当前界面的主要问题集中在状态表达、窄窗口任务优先级、错误恢复、设置提交安全性、隐私边界和可访问性。现有米白/橄榄绿视觉语言和桌面布局基础可继续使用，不做整页视觉重做。

## 设计目标

1. 用户能区分“正在加载”“没有内容”和“加载失败”。
2. 窄窗口下仍能快速完成最核心的本地文件上传。
3. 所有失败状态都提供安全、明确的恢复路径。
4. 未确认加载成功的设置绝不能被默认值覆盖。
5. 本地处理与云端 AI 处理边界在用户做决定前可见。
6. 交互控件具有唯一、可预测的键盘和辅助技术语义。

## 方案

### 1. 历史列表状态

保留现有 `historyNotice` 用于短暂成功/删除反馈，新增明确的历史加载失败状态或等价状态字段。侧边栏渲染规则为：

- `historyLoading`：显示加载中，不显示空态。
- 加载成功且 `historyItems.length === 0`：显示空态。
- 加载成功且有数据：显示列表。
- 加载失败：显示错误提示和“重试”，不显示空态。

重试复用现有列表加载路径，成功后清除失败状态；失败时保持失败状态并清理错误细节，避免泄露路径或内部异常。

### 2. 首屏与 New topic

桌面宽屏保持当前双栏顺序。`840px` 以下将上传卡片排在录音卡片之前，并通过稳定的 DOM/视觉顺序保证上传区域优先进入首屏。

`New topic` 继续调用现有工作区重置逻辑；重置完成后将焦点移到上传区域的可聚焦入口，并通过现有状态提示机制提供反馈。若上传区域处于错误态，焦点落到“重新选择”按钮而不是外层容器。

### 3. 设置加载与提交

增加“未加载、加载中、已加载、加载失败”的可观察状态。加载失败时：

- 显示可重试的失败提示；
- 禁用保存按钮；
- 不把初始 draft 当成已加载的持久化设置；
- 在成功加载前不允许提交任何设置。

语言偏好继续遵循当前立即生效的行为，但在控件旁明确标注；其余设置仍通过保存提交。设置页 footer 根据当前状态使用一致的操作文案和禁用原因。

### 4. 隐私、对比度与上传错误态

上传入口使用短句直接说明：音视频在本机处理；生成摘要/思维导图前，文字稿片段会在用户确认后发送给管理员配置的云端 LLM。中英文保持同一语义。

提高 `--text-muted`、`--text-soft`、`--warning` 等 token 的对比度，避免依赖低透明度表达禁用状态。错误态上传区域不再同时拥有外层 `role="button"` 和内层 button；交互态使用单一可聚焦入口，展示态使用普通容器。

录音能力探测失败或录音来源不可用时，提供“重新检查录音来源”；麦克风权限被拒绝时保留并突出系统隐私设置入口。

### 5. 低风险收尾

- 根据运行平台条件渲染窗口控制，避免在 Windows 上展示 macOS 交通灯。
- Credits 使用非交互状态行语义。
- 禁用更新操作旁提供原因/状态说明。
- 统一技术术语，优先使用用户能理解的中文表达并保留必要缩写。

## 测试策略

先为每个行为写失败测试：历史失败与重试、设置失败禁止保存、上传错误态无嵌套交互、New topic 焦点与状态、关键 CSS/文案约束。实现后运行前端完整测试、前端构建和 Rust 类型检查；最后按审查截图场景做手动复核。

## 非目标

- 不更换整体色板、字体或品牌风格。
- 不重构 Tauri/Worker 架构。
- 不改变本地转写和 AI 生成的业务边界。
- 不新增 Figma 或浏览器视觉稿。
